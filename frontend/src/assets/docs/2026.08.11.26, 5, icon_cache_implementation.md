**User**

Many Windows executable files and dynamically loaded libraries have icons, so an icon cache must be implemented to avoid slow down when the same icon should be obtained.
When an item is selected, if an icon is available for it, the icon should be displayed for now in two locations: 
in the rightmost section "Properties" (where the file path is shown) and on the left side of the window (in the "Windows" section) — next to each list item.
Since the retrieved icons may be in .ico format—which requires conversion on the Go side into a format compatible with the UI technologies being used—the target format must support transparency (such as .png).

I believe the icon cache should be implemented on the web application side, while the retrieval of these icons should be handled by the Go side. 
Requests for icons could cover multiple files or just a single additional file—specifically, one for which the icon has not yet been cached.

You do not need to update the icons in the middle section of the application window, where the control element hierarchy is displayed.

For state management, use libraries like Jotai or Valtio (whichever is more suitable) rather than standard React tools like useState.
Implement the new functionality in separate folders so that it does not mix with the rest of the code.

The icon retrieval process is a background task, so application performance should not suffer; furthermore, the icon's on-screen size should not change when it is loaded—meaning there should be no visual jumping.

The application uses the smallest icon size; therefore, when extracting the image from the icon file, it must be rendered at the smallest size contained within the icon but with the highest color resolution.

### Backend (`backend/fileicon/`)
- Pulls the first icon group from PE resources (exe/dll), or reads `.ico` files directly
- Selects the **smallest** image, preferring the **highest bit depth** on ties (PNG-in-ICO treated as 32-bit)
- Converts to **PNG with transparency** (`data:image/png;base64,...`)
- Falls back to `ExtractIconEx` when PE extraction fails
- New API: `GetFileIcons(pathsJSON)` — batch or single path
