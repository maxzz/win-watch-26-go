# Highlighting behavior adjustment
_Exported on 8/11/2026 at 21:37:03 PDT from Cursor (3.15.19)_

---

**User**

In the central panel (the "Control Hierarchy" panel), if the auto-highlighting option for the window's bounding rectangle is enabled, clicking a selected item again triggers the highlight effect again. 
However, in the left panel (the "Windows" panel), the function is implemented such that highlighting occurs only on the first click—provided auto-highlighting is on—but not on subsequent clicks. 
The behavior needs to be changed so that highlighting occurs both upon the initial selection and upon any subsequent selections of the same item, provided the auto-highlighting option is enabled.

---

**Cursor**

I'll compare how the Windows panel and Control Hierarchy panel handle selection + auto-highlight, then align the left panel so re-clicking a selected item re-triggers the highlight.

The Windows panel sets `selectedHwndAtom` directly, so re-clicking the same handle is a no-op; I'll add a select path that re-triggers auto-highlight like the control tree.

I'll add a `selectWindowAtom` that re-triggers auto-highlight on re-click, and wire the Windows panel to use it.

The Windows panel was writing `selectedHwndAtom` directly, so a second click on the same window was a no-op and never re-ran auto-highlight. The Control Hierarchy panel already re-highlights because `setSelectedControlAtom` always runs its highlight logic.

**Change:** added `selectWindowAtom` and wired the Windows panel through it. On a new window it only updates selection (highlight still comes from control-tree auto-select). On a re-click of the same window with auto-highlight enabled, it re-runs highlight for the current selected control (or the tree root as fallback).
