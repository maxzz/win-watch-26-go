I'll start by reading the picker control and tracing how window selection and the list stay in sync.

The header already tries to insert then select; I’ll check how the tree applies that selection when the window is missing from the list.

Picking currently selects first and refreshes afterward, so a window missing from the list never becomes a selectable row. I’ll refresh (or insert) the list first, then select the matching item.

When the picker finishes, the window is now selected **from the list**, and the list is brought up to date first if that row is missing.

Previously the header selected immediately, then refreshed. A window that was not already listed never became a real row, so nothing in **Top Windows** could stay selected.

On release the flow is now:

1. If the top-level window is already in the list, select that row.
2. If it is not, refresh the list from the OS, then select the matching row.
3. If a refresh still does not include it (untitled, hidden, or filtered out), add it to the list and then select it.

The picker control stays generic; this list-then-select behavior is wired from its `onReleased` callback in the windows header.
